## Context

`portfolio/` 当前以月结单快照为资产底座，并补充手工交易、成本覆盖、仓别和金字塔计划。现有实现存在三类根本问题：交易净现金被当成当前持仓成本；缺失成本按零进入总体盈亏；计划只和 USD 闲置现金做简单比较且没有纳入当前持仓。用户已确认平台应围绕仓位、现金流和成本建设，账面成本与外部净投入必须同时存在，安全加仓以持仓内集中度和现金安全线为硬约束，同股多个方案需要可比较。

现有 `portfolio/server/data/local.db` 必须原地兼容，前端必须保留已有浅色卡片、黄色品牌色、表格和 ECharts 风格。原始月结单继续在浏览器端解析，服务端只接收结构化数据。

## Goals / Non-Goals

**Goals:**

- 建立可审计的外部资本与收益/费用事件账本，保证反复交易不重复增加净投入。
- 可靠地区分当前账面成本、外部净投入、已实现/未实现资本利得及现金流。
- 以后端统一输出可解释安全金额和同股方案比较。
- 把资产总览、持仓分析、现金流、加仓计划和数据管理拆成职责清晰的页面，同时保持现有视觉语言。
- 对旧数据库做增量迁移，对缺数据明确返回 incomplete，不自动伪造历史事件。

**Non-Goals:**

- 不连接券商交易执行 API，不自动下单。
- 不把股价、PE 或趋势信号升级为资金决策约束。
- 不猜测无法归属的融资费用，也不从部分交易历史反推可靠期初成本或外部净投入。
- 不在本期建立税务级别的 FIFO/ACB 成本引擎；交易型持仓缺少券商/人工成本时标为待补录。

## Decisions

### D1 资本事件与内部交易分账

新增 `capital_events` 保存 `cash_in`、`cash_out`、`transfer_in`、`transfer_out` 和 `adjustment`。事件金额使用原币并保存日期、来源、券商、市场、标的、数量和单位成本；转仓金额由数量乘用户确认成本得出。净投入只汇总这些事件，买卖、股息与费用永不自动改变净投入。

选择独立资本事件表而不是复用 `trades`，因为两者回答的问题不同：交易描述资本如何在组合内部流动，资本事件描述有多少外部本金进入或离开。对旧用户不生成猜测性期初事件，summary 返回缺失提示并引导确认。

### D2 收益费用事件与现金流视图

新增 `cash_flow_events` 保存股息、已实现资本利得、交易费补录、融资费及其他明确收益/费用。交易买卖和交易表内手续费不复制入表，查询现金流时在服务层与资本事件、交易记录合并；来源 ID 用于导入幂等。

股息以毛额、税费和净到账表示；预算只按净到账恢复。融资费用不带标的时只进入整体盈亏。已实现资本利得只有在券商导入或用户明确录入时计入，避免根据不完整交易历史猜测成本法。

### D3 账面成本来源不再使用交易净额

当前持仓账面成本优先级固定为人工确认覆盖，其次为最新券商快照。只有具备完整、明确成本口径的数据才可计算未实现盈亏；仅有手工交易而无可靠成本的持仓保留数量与估值，但成本和相关盈亏返回 `null`。

整体与单股响应同时返回 coverage/issue codes。整体已知盈亏仍可展示，但 UI 必须标注“部分数据”，不得用零填充未知成本。

### D4 盈亏采用解释层与经济层双对账

解释盈亏为：已实现资本利得 + 未实现资本利得 + 净股息 − 交易费用 − 融资费用。经济盈亏为：当前净资产 − 账户外部净投入。两者差额作为未解释差额公开展示，用于暴露缺流水、汇率差或成本口径差。

单股盈亏只包含可归属资本利得、股息和交易费用；未归属融资费用只在整体层。外部净投入既可按账户汇总，也可按事件明确关联的标的汇总，不进行比例摊派。

### D5 风险规则和仓预算独立建模

新增 `risk_settings`，默认标的/仓持仓上限 0.5、最低现金率 0.3。新增 `bucket_budgets` 作为按季度版本化的持续资金上限：首次设置不算调整，同季度允许一次后续修改；跨季度新版本不重置资金占用。

仓占用以可归属实际资本流计算：转仓入成本和买入净支出增加，占用；卖出净回款和股息净到账减少，占用；占用下限为零，可用预算不超过上限。标的跨仓时保存事件发生时仓别，避免当前仓别改动篡改历史。

### D6 安全金额以后端统一模拟

所有金额先转为 USD 基准。设当前持仓总市值 `H`、目标标的市值 `S`、所属仓市值 `B`、现金 `C`、总净资产 `A`、预计费用 `F`，通用集中度额度为：

```text
symbolRoom = (symbolLimit × H - S) / (1 - symbolLimit)
bucketRoom = (bucketLimit × H - B) / (1 - bucketLimit)
cashRoom   = C - cashFloor × A - F
budgetRoom = bucketBudgetAvailable - F
safeAmount = max(0, min(symbolRoom, bucketRoom, cashRoom, budgetRoom))
```

返回四项额度、瓶颈、加仓前后比例、数据日期和缺失约束。没有仓别、预算、现金或估值时返回 `safeAmount=null`；空仓/单标的组合不提供隐式例外，用户只能显式修改可配置规则。

### D7 方案比较使用当前持仓上下文

扩展计划场景名称并增加后端 preview/compare。每档计算当前持仓加累计计划后的数量和账面均价；同股方案才能比较。1:2:4:8、1:2:3:4 等模板先归一化为权重，再按相同预算分配。方案保存预计总交易费用，并按累计投入比例分摊到各档；费用同时占用现金与仓预算，并计入加仓后的账面成本。

超限方案可作为草稿保存和比较，但不能标记成交。成交标记必须在事务内重新校验；在券商成交尚未同步回账本前，同一用户只允许一个方案保留已成交档位，同方案后续档位则按累计结果复核。已有成交档位的方案先取消成交标记后才能编辑。这是当前没有订单/资产同步机制时的保守资金锁，避免多个单独安全的方案重复占用同一现金与仓额度。

原币计划先折算到 USD 完成风险计算，再同时返回原币与展示币种结果。已有计划保持可读，新增字段提供兼容默认值。

### D8 增量迁移和 API 兼容

`db.ts` 引入 `schema_migrations` 和幂等迁移步骤，新增表与索引，不删除旧表/列。`summary` 保留 `totalCost`、`gainLoss` 等旧字段作为兼容别名，同时新增明确命名字段和 completeness；旧成本错误测试改为验证账面成本与净投入分离。

旧月结单中的“美国市场 / 香港市场”等市场名称在服务层统一规范化为 `US / HK`；旧 `symbol_buckets` 继续作为 `instrument_buckets` 尚未建立时的只读回退。迁移不得要求用户重新上传月结单或重新分仓。

资本事件、现金流、风险设置、预算、安全计算和计划比较均使用独立 REST 路由。服务层是计算唯一来源，React 不复制公式。

### D9 页面职责与现有风格

导航调整为资产总览、持仓分析、现金流、加仓计划、数据管理。资产总览首屏为净资产、持仓、账面成本、外部净投入、现金与盈亏分解；图表和行情下移。持仓页聚焦占比、成本和单股盈亏；同一市场同一标的先聚合为决策行，券商持仓只作为可展开明细，标的级股息、实现收益、费用和净投入不得在多个券商行重复展示。月结单与交易录入迁到数据管理。加仓页首屏显示安全金额和方案比较，TradingView 放入次级折叠区。

不引入新 UI 框架，复用现有 CSS token 与组件风格。新增响应式断点、移动端卡片化档位、语义按钮、表单 label 和 focus-visible，确保 390px 无页面级横向滚动。

## Risks / Trade-offs

- [旧用户没有外部资本历史，经济盈亏暂时不可算] → 不自动填充；提供明显的数据补录入口和 coverage 提示。
- [部分交易流水无法可靠推导已实现盈亏] → 只使用券商导入或用户确认的实现收益，保留未解释差额。
- [静态即期汇率使历史对账存在差额] → 每条新事件保存使用汇率并在响应中暴露，旧记录标记汇率口径有限。
- [单标的严格 50% 会令空仓无法单票建仓] → 不做隐式豁免；风险规则可显式调整，UI 说明其后果。
- [卖出/股息恢复预算依赖完整流水] → 返回预算 coverage；缺流水时安全金额不宣称完整。
- [页面重构范围较大] → 保留视觉 token 和旧 API 兼容字段，按后端、共享类型、页面逐步落地并做浏览器回归。

## Migration Plan

1. 创建并记录 schema migration，新表/索引在事务内幂等落库。
2. 保留原快照、现金、交易、成本覆盖、仓别和计划；停止用交易净额覆盖账面成本。
3. 不为历史用户自动创建资本事件；summary 返回初始化指引。
4. 先上线兼容响应与新 API，再切换前端页面；旧字段在本期不删除。
5. 对旧 `local.db` 和全新内存库分别运行测试；迁移失败时事务回滚，旧表不变。

## Open Questions

- 后续若券商数据能证明交易历史完整，再单独引入可选择 FIFO/移动平均的成本重放能力；本期不猜测。
- 税务预扣与股息净额的券商字段映射将随真实样本补充，本期保留人工确认入口和来源字段。
