# Design: dashboard-redesign

## Context

总览页现状：5 KPI 卡 + 累计盈亏/安全边界两卡 + 三饼图 + 市值/成本历史图。绩效页已有 performance API（月度净资产/NAV/流量）。设计稿评审结论与用户拍板：浅色 hero（B 案）、保留分段切换器、时间档 6月/1年/全部。

## Goals / Non-Goals

**Goals:** hero 双线图（月度粒度、诚实带点折线）；持仓分布信息密度升级；盈亏拆解百分比化；安全边界表格化；数据截至标注。
**Non-Goals:** 日频平滑曲线（等每日快照）；「持仓数量 ≥8」类新风控规则（无对应设置项）；黑色 hero（已否）；绩效页改动（状态/绩效分页决策不变——hero 是资产状态的时间维度，NAV/TWR 仍归绩效页）。

## Decisions

- **D1 累计净投入序列在服务端算**：`performance()` 对 flows（已按 scope 过滤）做前缀和，首个快照月之前的存量事件计入基线——两线起点即对齐真实本金；客户端 cumsum 会丢基线，故放服务端
- **D2 hero 数据源用 performance API**（Dashboard 新增并行请求），不复用 summary.history（无现金、无净投入、券商缺月塌陷）
- **D3 双线口径**：净资产 = 月末快照（含 carried 空心点语义沿用绩效页）；净投入 = MWR 视角本金线；两线间距 = 经济盈亏，与盈亏拆解合计行同源
- **D4 堆叠条/排名表用 CSS+HTML 不用 ECharts**：静态比例条无交互需求，DOM 渲染更锐利且省初始化开销；配色沿用 PALETTE（按标的）与既有三仓色（按三仓）
- **D5 状态词三档**：充足（gain 绿点）/正常（brand 黄点）/超限（loss 红点）；判定：现金率 ≥下限+5pp 充足、≥下限 正常、否则超限；集中度 ≤上限−5pp 充足、≤上限 正常；预算剩余 >20% 充足、>0 正常
- **D6 时间范围切档纯客户端 slice**，不重新请求

## Risks / Trade-offs

- [月度点少时双线图稀疏] → 诚实呈现（当前仅 1 点则显示单点+空态提示），随月结单积累自然成线
- [移除市值/成本历史图丢失账面成本趋势] → 账面成本仍在 hero 底部条与盈亏拆解中；如怀念趋势图可在绩效页恢复

## Migration Plan

前端为主 + performance API 增量字段（向后兼容）；重启本地 server 生效；可整体回滚。
